# L2/19-186

## 要約

Unihan ad hoc group が、Unicode 13.0 向けに旧 `kZVariant` データのほぼ全面的な見直しと、spoofing variants 用の新 field を提案した報告である。
旧データは CCCII の構造の誤解に基づく機械生成で、当時校正されず、品質が低いと説明する。
Z-variants の意味・abstract shape の同一性と、意味を問わない視覚的な紛らわしさを区別する。
両 field のデータを生成・review し、UTC \#160 前に提出する方針を示す。report 自体は UTC の採択記録ではない。

## 報告内容

### 旧データの問題と作り直し

本文2頁は、旧 `kZVariant` データが CCCII の構造の誤解に基づいてアルゴリズムで生成され、当時校正されなかったと述べる。本文4頁は、正式に記録・検証された少数の pair を除き、既存内容をほぼ全面的に取り除く方針を示す。新データの根拠には ISO/IEC 10646 Annex S §S.3 の source separation 例を挙げる。

### Z-variants と spoofing variants

- Z-variants は、同じ semantics と abstract shape が誤りや source separation によって複数回符号化された関係として説明する。
- Spoofing variants は、意味にかかわらず似た glyph が利用者を誤認させ得る関係。意味が異なる `土` / `士`、`未` / `末` も例に挙げる。
- Z-variants と compatibility variants も視覚上の spoofing に関係するが、新 field にはそれら以外の spoofing variants を入れる構想。
- 新 field 名は `kSVariant` を推奨し、`kSpoofingVariant` などを代案に挙げる。後の正式名称とこの段階の仮称を区別する。

### データと review

両 field は有用だが網羅的ではない provisional data とし、Unicode 13.0 では実用性の高い URO を優先する。author らがデータを生成・review して UTC \#160 前に提出し、将来の追加は UTC action item に基づくものに限るよう提案する。これは report の提案であり、恒久的な採択済み規則としては扱わない。

## 後続決定

[UTC \#159 minutes](https://www.unicode.org/L2/L2019/19122.htm#159-C11) の `159-C11` / `159-A50` / `159-A51` は、新 field（議事録表記 `kSpoofVariant`）を記述する UAX \#38 proposed update と public review を進めた。`kZVariant` の個別 pair の採択を記録するものではない。

後続データは [L2/19-281](utc-l2-19-281.md) / [L2/19-282](utc-l2-19-282.md)、review 上の指摘は [L2/19-328](utc-l2-19-328.md)、確定データは [Unicode 13.0 の見直し event](../events/unicode-13-kzvariant-data-overhaul.md) を参照。

## 論点

この報告は大量削除の全体的な理由を示すが、削除された各 pair について誤りを証明する一覧ではない。また、semantic folding のための Z-variant と security のための視覚的類似は用途が異なる。削除を自動的に `kSpoofingVariant` への移行と解釈しない。
