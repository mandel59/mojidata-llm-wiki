# IRG N2786

## 要約

`IRG N2786` は、U+980B 頋と compatibility ideographs U+FACB / U+2F9FF にまとめられていた字形を、字音・字形・字義の違いに基づいて分離する原提案である。Kangxi Dictionary、CNS 11643、《大漢和辞典》、文字情報基盤、KPS 10721 の資料を比較し、五果切の 頋 と古暮切の 顧 variant は non-cognate だと論じる。

文書は、KP1-869A と T6-6430 を新規 code point へ移し、U+FACB / U+2F9FF には historical source references を残す案を示した。後続 review では移動先が既存 U+2EA07 に変更されたため、本書は最終 disposition ではなく、disunification の必要性と source ごとの初期整理を示す提案として読む必要がある。

## 提案内容

### 頋と顧 variant の分離根拠

文書は、U+980B の代表字形が上部に `㔾` を持つ五果切の字である一方、U+FACB / U+2F9FF の一部 source glyph は上部に `巳` を持つ顧の俗字系だと整理する。Kangxi Dictionary の別 entry、CNS 11643 の別 code、辞書での発音・配列の違いを根拠に、両者を単なる glyph variation として同じ unified ideograph に置くべきではないとした。

### source ごとの整理

| Source | 文書の分析と提案 |
| --- | --- |
| T | T3-4552 と T6-5A33 は現行 chart では同形だが、旧 proposal では first stroke に差があるため glyph correction を求める。T6-6430 は U+2F9FF から分離対象とする。 |
| J | JMJ-028161 は五果切の U+980B 系、JMJ-028162 は顧 variant 系と分析し、後者を分離先へ移せるとする。 |
| KP | KP1-8696 と KP1-869A は KPS 10721 の発音と配列で区別され、KP1-869A を U+FACB から移す対象とする。 |
| G | Kangxi source を顧 variant 系の分離先へ horizontal extension できるとし、U+980B の G-source reference 見直しも候補に挙げる。 |

U+FACB / U+2F9FF の residual stroke count は、対象字形の構造に合わせて 4 から 5 へ直すよう提案する。

### 初期 disposition

文書末の表は、U+FACB に `KPU-0FACB`、U+2F9FF に `TU-2F9FF` を残し、別の新規 code point に `GKX-1402.14`、`T6-6430`、`JMJ-028162`、`KP1-869A` をまとめる案を示す。これは IRG Meeting \#64 に提出された初期案であり、既存 U+2EA07 を使う後続案より前の disposition である。

## 後続決定

[IRG N2834](irg-n2834.md) は《廣韻》6 editions と Unihan reading properties を比較し、KP1-869A / T6-6430 を新規 code point ではなく既存 U+2EA07 に unify する Solution 2 を提示した。[IRG N2865](irg-n2865.md) で TCA が T6-6430 の U+2EA07 への移動と `TU-2F9FF` の付与に同意した。

[IRG N2826](irg-n2826.md) の M65.05 は、この後続案に基づく disunification を unanimously accept し、KP1-869A と T6-6430 を U+2EA07 に置くよう WG2 へ勧告した。[IRG N2892](irg-n2892.md) は Meeting \#65 時点の source migration を一覧化している。

## 論点

### 原提案と採択案の違い

`IRG N2786` が直接提案したのは新規 code point への分離であり、U+2EA07 への統合ではない。disunification の字形・字音上の根拠は本書に遡れるが、最終的な移動先と property disposition は `IRG N2834`、`IRG N2865`、M65.05 を参照する必要がある。

### compatibility mapping と source identity

後続処理は U+FACB / U+2F9FF の compatibility mapping を U+980B のまま維持しつつ、KP / T source references を別 code point へ移す。compatibility equivalence、dictionary identity、regional source glyph を同じ関係として扱わないことが、この case の中心的な論点である。
