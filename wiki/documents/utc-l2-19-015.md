# L2/19-015

## 要約

John H. Jenkins が [L2/15-266](utc-l2-15-266.md) を大幅に改訂し、Unicode 13.0 向けに `kZVariant` の全面見直しを提案した。
品質が不均一な既存データを、source separation 例と確認済みの重複・統合誤りから作り直す。
関係の種類、locale、出典を記録する syntax も提案するが、本文は完成した置換データではない。
UTC \#158 の後続指示はまず Unihan mail list での議論であり、提案全体の採択とは区別する。

## 提案内容

| 対象 | 提案 |
| --- | --- |
| 定義 | 通常なら統合可能な形が source separation、non-cognate rule、統合誤りによって別符号化された場合を説明する。別の文言案も検討するとする。 |
| データ | 既存データを全面置換し、ISO/IEC 10646 Annex S §S.3 の例と既知の統合誤りを使う。Eiso Chen、Henry Chan、Richard Cook の一覧を候補資料に挙げる。 |
| 整合性 | 推移性と対称性を確保する。原文の “reflexive” の説明は A→B なら B→A であり、対称性を指す。 |
| Syntax | `[DINSU]` による関係分類、IRG source に対応する locale、Unihan field tag による出典を追加する案。 |
| 作業 | author が Unihan Subcommittee とデータを作成し、Unicode 13.0 向けに登録する想定。 |

## 後続決定

[UTC \#158 minutes](https://www.unicode.org/L2/L2019/19008.htm#158-A58) の `158-A58`（2019-01-15）は、John Jenkins に Unihan mail list で議論し、2019年第2四半期の UTC に結果を持ち帰るよう指示する。実際のリリース結果は [Unicode 13.0 の見直し event](../events/unicode-13-kzvariant-data-overhaul.md) を参照。

## 論点

### 提案 syntax と確定仕様

Unicode 13.0 の [UAX \#38 Revision 28](https://www.unicode.org/reports/tr38/tr38-28.html#kZVariant) は、この提案の関係分類・locale syntax を採用していない。提案の regular expression を実装仕様として扱わない。

### 置換データの根拠

[L2/19-186](utc-l2-19-186.md) が旧データの生成上の問題と新 field との境界を説明し、[L2/19-281](utc-l2-19-281.md) が後に初期データを提出する。全面見直しの理由と個々の関係の採否は別に確認する。
