# L2/26-217

## 要約

`L2/26-217` は、Kip Cole が [PRI \#555](pri-555.md) の finite automata data を Elixir の `unicode_string` に実装した経験に基づく public review feedback である。提案を支持し、Unicode 18.0 の公開表を四つの break type に採用したと報告する。

筆者の測定では、従来実装が `LineBreakTest` の 19,346 件中 19,309 件に合致したのに対し、DFA 実装は全件に合致した。性能は line breaking で改善したが、word breaking では遅くなり、最適化前の表駆動実装はさらに遅かった。これらは当該 Elixir 実装での測定であり、一般的な性能保証ではない。

## フィードバック内容

- 手書きの UAX \#14 規則実装では、規則の欠落に加え、`General_Category` や `East_Asian_Width` による文字集合の導出を近似したために誤判定が生じた。公開 symbol table はその集合演算を明示できる。
- 擬似コードの end-of-text 記号と `Last_Accepting_Position` の初期化、dictionary 対象 script の識別、辞書が返す境界の扱いを明確にするよう求める。
- symbol files が要求する UnicodeSet 構文の範囲、symbol / state indices の公開、規則本文と表が食い違う場合の優先関係、CLDR locale tailoring の適用方法を明示するよう求める。
- 筆者の実装では、Latin-1 symbol lookup と ASCII pair lookup の最適化後、line breaking は従来の約 51% の時間、word breaking は約 128% の時間を要した。

## 後続決定

この文書は feedback であり、UTC の採否を記録しない。PRI \#555 の closing date 以降の disposition を確認する。

## 論点

[L2/26-135](utc-l2-26-135.md) の実装可能性を支持しつつ、UnicodeSet と [Unicode Set Notation](../topics/unicode-set-notation.md) の依存関係、辞書方式による CJK / 東南アジア言語の break、CLDR tailoring が残る実装上の境界を示す。
